## 泰坦使用

### 登乘与驾驶舱 HUD（2026-11-23 继续扩展）

在本地游戏或监听主机，走近可驾驶的泰坦（例如君主或离子），瞄准机体碰撞体，出现「登乘泰坦」后按使用键（默认 E）开始约 0.8 秒的连接。玩家的使用射线必须先摸到机体；`EmbarkRange` 的默认 200 单位是座舱额外的距离上限。普通战斗泰坦的 NPC 与座舱共用一个物体，两者收到使用事件时均交给同一座舱判断。地图上的装饰模型和没有座舱的边境防御单位不能驾驶。过渡中走远、被墙遮挡、机体死亡或座舱被占用时取消；库存暂停状态恢复到进入前的值。登乘成功后机体转为玩家友军，离舱后可继续作为友方 AI 跟随。此控制链当前支持本地玩家和监听主机。

座舱使用原生 `ScreenPanel` / `PanelComponent`，显示机体生命与护盾、当前弹匣／装填、目标阵营、强力的追踪标记、攻防与冲刺冷却、核心充能／蓄力／生效剩余时间，以及当前输入绑定。按使用键离舱：检查沿途世界／导入的 PlayerClip、完整玩家体积、头顶空间、地面和坡度；无法安全离舱会显示出口受阻。驾驶扫掠额外包含 `TitanClip`。禁用、销毁或致死时先解除玩家父子关系，恢复库存与原生移动模式。

`Titanfall2TitanSeat` 的 `EmbarkSeconds`、`EmbarkRange`、`AlignWithPilot`、`ShowHud`、`ShowCockpit` 和 `CoreAction` 可在预制体组件中配置。核心默认绑定已有的 `flashlight` action（Sandbox 键盘默认 F，手柄方向键上），HUD 读取实际绑定。座舱使用原版轻／中／重三种 POV 模型及闭舱待机姿态，按模型 `CAMERA` 附件对齐镜头；未接入原版完整登舱演出和逐机体相机动画。

#### 原版脚本与 UI 适配

本轮直接对照 `D:/northstar/scripts/vscripts/client/cl_titan_cockpit.nut`、`client/rui/cl_weapon_status.gnut` 和 `earn_meter/cl_earn_meter.gnut`：

- 原版 `ajax_cockpit_base` 独立追踪 `healthFrac`、`shieldFrac`、`dashFrac`；底部 `ajax_cockpit_lower` 与独立仪表按 `COCKPIT_HUD_BOTTOM`／`COCKPIT_OBJ_1` 附件建立拓扑。能力、弹药和 `earn_meter` 使用另一组普通 HUD 拓扑。
- 本引擎的原生屏幕 UI 按这个状态分工，并结合用户提供的原版画面安排：顶部中央原版分段血条／护盾，左下核心环及攻防图标，旁侧紧凑弹药，底部中央冲刺条。技能恢复条与冲刺条连续读取实际冷却；当前只有一次冲刺库存，不绘制虚假的双冲刺储量。强力火箭还要求三层锁定才显示就绪。
- 核心环积累时显示充能，生效时显示剩余时间比例，采用 0.7 秒填充过渡；智能核心无限弹药期间显示 `∞`。没有把弹匣容量冒充备用弹药。生命分段素材也会在最大生命改变时重新选择。
- 原版技能、核心、机体、武器和血条素材仍通过本机挂载读取。登乘期间隐藏战斗仪表；离舱清理整个 HUD。机体外壳通过当前驾驶相机的独立标签排除，其他相机仍可渲染机体；相机替换或座舱销毁时移除过滤。

这不是执行原版 RUI 虚拟机。可读脚本能确认层级、附件和状态参数，编译资源中的像素布局、曲面绘制与动画轨迹仍需适配；当前血条与冲刺条使用屏幕空间位置，尚未按原版曲面和底部附件绘制。小地图、边境防御波次等仍需要相应玩法数据。

### 六种核心

`Titanfall2TitanCore` 随普通泰坦预制体生成，`Actor` 引用在克隆后指向同一机体。主机维护 `Charge`（0–1）、`ChargeupRemaining`、`ActiveRemaining` 和 `UpgradeLevel`；HUD 只读取状态。核心通过原版每机体的被动积累时间与有效伤害充能；伤害阈值 `DamageForFullCore=10000` 是本适配的可调平衡值。友军、过量击杀的额外伤害、被完全格挡的伤害和核心自身伤害不会额外充能。护盾实际承受的伤害可以充能。

| 机体 | 核心当前行为 |
| --- | --- |
| 君主／BT | 升级核心补满护盾，固定默认路线依次启用 Arc Rounds、快速装填和 XO-16 加速器；升级最多三阶，重复激活不会无限叠加容量。换装保留永久升级。 |
| 离子 | 激光核心有蓄力和持续光束，按主机瞄准与遮挡连续判伤，使用原版激光核心 PCF。 |
| 军团 | 智能核心在有效时间内提供可见目标辅助瞄准与无限弹药；不会瞄准遮挡后的目标。 |
| 浪人 | 剑核心替换主枪为原版剑，主攻击有前摇和接触扫掠，可躲避、不能穿墙；同时加强格挡与冲刺恢复。 |
| 强力 | 齐射核心读取原版武器参数，20 组、每组三枚导弹按瞄准点持续引导，核心导弹不会给下一轮核心充能。 |
| 烈焰 | 火焰核心沿地形发出三道地面波，共享受害者集合，重叠波道不会多次叠加同一轮核心伤害；墙、陡坡和断崖可阻断。 |

北极星飞行核心当前明确显示尚未接入。六种核心已实现本引擎中的基础行为，尚未完整复现原版动画图、镜头、音频事件混合和全部技能细节；君主不是自由选择升级树，强力导弹与烈焰地面波也属于当前引擎适配。

### 追踪武器、集束与 NPC 战术

泰坦攻击武器从当前挂载快照读取原版 WeaponData，保留继承和多人覆盖，对应的模型、排气附件、尾烟、命中表、伤害与齐射节奏。强力 40mm 的每枚追踪标记分别在 15 秒后过期；同一目标累计三枚后才能释放六发追踪火箭，发射消耗标记。导弹保持原目标，目标死亡后停止后续齐射。北极星集束改为五秒内二十次分布式局部爆炸，每次独立检查遮挡和衰减并使用原版二次爆炸表；尚未逐实体复现原版随机子弹药。

步兵和幽灵可使用有库存、冷却和前摇的原版破片雷。主机先检查弹道、天花板、自身与友军风险；低抛受阻可尝试高抛，失去目击后只使用最后看到的位置。投掷中死亡或禁用会取消待释放的手雷；场景内待投与在飞的 NPC 雷合计最多六枚。步兵默认武器来源于原版 AI 设置，幽灵投雷是可配置的战术扩展。死神、幽灵、等离子炮台和泰坦死亡使用对应原版 PCF，表现对象独立于尸体清理，不代表恢复了原版全部爆体条件或碎肢。

玩家与有机 NPC 使用肉体命中，机器人使用原版机械命中，泰坦使用 `metal_titan` 命中类别；核心激光与剑不再沿用普通枪械弹孔。枪械／核心／死亡粒子均补充按需优先读取的 PCF 映射，避免短命效果等待完整后台目录。

## 独立武装预制体

路径为 `mount://titanfall2/entities/titanweapons/mp_titanweapon_<id>.prefab`，标签 `titan-weapon`：

`xo16_shorty`、`xo16_vanguard`、`predator_cannon`、`particle_accelerator`、`leadwall`、`sniper`、`sticky_40mm`、`meteor`。

```csharp
// 在主机游戏逻辑中安装。也可在编辑器给预制体的 Actor 字段指定机体。
var preset = GameObject.GetPrefab(
    "mount://titanfall2/entities/titanweapons/mp_titanweapon_leadwall.prefab" )
    ?.Clone( titan.WorldPosition );
var armament = preset?.GetComponent<Titanfall2TitanArmament>();
if ( armament?.EquipTo( titan ) == true )
    preset.Destroy(); // 配置已经安装到机体，展示对象可以移除。
```

安装保留零售脚本弹速、散布、弹丸数、伤害和装填参数；当前弹匣清空并重新装填，避免切换武器获得免费弹药。更换后的模型、声音与投射物配置由主机同步。

## 命中、爆炸与资源限制

`CombatEffects.cs` 按当前挂载内容快照读取 `scripts/impacts/<table>.txt`。已知表面从原版 surface properties 的 `gamematerial` 选取 FX／声音；有机 NPC 使用肉体效果，机器人和泰坦使用金属效果。世界碰撞没有原版表面名时按混凝土兜底。

武器按原版多人脚本读取第一／第三人称枪口、抛壳、曳光、弹道尾迹和命中表，交给 PCF 转换器，使用游戏安装中的原版贴图、模型、动画图集和调色纹理。普通射击不再叠加 s&box 默认枪口、弹壳或通用烟尘／火花。PCF 使用的自定义着色器必须随包编译和安装，只有 `.shader` 源码的测试包不能验证粒子画面。命中特效仍跳过尚不支持的投射贴花、折射、乘法混合和独立不透明度精灵；支持的非加法烟尘保留。未支持的层不会用另一套通用特效补齐。

弹孔／焦痕使用原版 `decals/bullets/*/shot1` 和 `decals/scorch1` 的颜色、法线与遮罩，按原版 `_subrect.vmt` 的 `$size`／`$decalscale` 确定尺寸，依附命中物体，20 秒清理。尺寸只写入 DecalDefinition 一次，原生组件 Size 保持 1，避免两次相乘把 128 单位焦痕放大到 16384 单位。不会把弹孔贴在 TF2 NPC 或玩家皮肤上。已知水、黏液与护盾表面不生成硬表面弹孔。每场景最多 128 张痕迹、64 组瞬时命中特效。爆炸和电弧伤害仍要求主机与遮挡检查；重甲爆炸伤害单独读取 `explosion_damage_heavy_armor`。

## SMR 与铁驭投掷物

2026-11-23 的专项修复使用本机零售资源及 Northstar 的原版武器脚本作对照：

| 武器 | 当前表现与触发 |
| --- | --- |
| SMR | 当前绑定姿势的网格弹头沿本地 +Z；显示模型与 `exhaust` 附件一同旋转，使弹头沿飞行 +X、排气向后。`Rocket_Smoke_SMR` 从该附件发出；命中读取 `exp_smr`，保持小型火箭爆炸。弹体消失后已有尾烟短暂保留并清理。 |
| 破片雷 | 读取 3.25 秒引信，碰撞弹跳；引信结束使用 `exp_frag_grenade` 的 `airburst`，不在空中投射地面弹痕。 |
| 电弧雷 | 使用原版蓝色投掷尾迹及 `exp_emp`，不额外叠加普通子弹直接伤害。 |
| 火飞镖 | 命中后播放 `P_grenade_thermite`，沿表面法线定向并跟随附着物，持续 6 秒；不再先播放破片雷爆炸。 |
| 重力星 | 使用 `P_wpn_grenade_gravity`，吸附阶段结束再播放 `exp_gravity_grenade`，不在部署时提前爆炸。 |
| 电烟雾 | 使用 `P_wpn_smk_electric_pilot` 的烟雾与电弧，持续 5 秒；不再借用编辑器的通用烟雾预制体，也不叠加普通破片爆炸。伤害从部署 1 秒后开始。 |
| 炸药包 | 保持附着和遥控起爆；爆炸保留命中面信息并读取 `exp_satchel`。 |

普通单帧 legacy 粒子同样直接读取其 VTF。此前只有动画／图集进入 VTF 路径，普通单帧会落到同名 RPAK 纹理，丢失泥土粒子的透明遮罩，使 SMR 爆炸出现方形灰块。现在使用原版 VTF 的 alpha；原生运行检查实际读取 GPU 纹理确认遮罩范围为 0–255。

短命爆炸不再等待后台顺序扫描全部 PCF。炸药包、破片／电弧雷、SMR、火焰星、重力星和电烟雾按原版粒子所属的 PCF 优先准备，并在子效果依赖可用后创建；后台扫描跳过已经读取的库。冷启动检查不预先填满粒子目录，炸药包走实际持有武器的副键起爆路径，同时验证原版爆炸图、活跃渲染粒子和截图；无法解析或创建时输出具体粒子名的警告。

投射物逐步飞行、视点到枪口的空间检查、瞄准落点和爆炸遮挡均使用 `Titanfall2TraceMask.Grenade`。这样能命中原版导入中以 trigger 形状保存的 `BulletClip`，同时忽略纯 `PlayerClip` 和普通触发区。原生查询一次填满 8 个 any-tag 槽位时会失去筛选，内容掩码现分为最多 7 个标签一组并取最近命中；`StartedSolid` 也保留为阻挡结果。弹体停在扫掠碰撞中心后再释放尾烟，贴墙枪口不会在遮挡另一侧生成弹体。

普通枪械、NPC 视线与射击、智能手枪锁定、泰坦激光和电弧查询现按 `Shot` 掩码选择最近表面；近战使用 `ShotHull`，区域伤害和地面波使用 `Grenade`。普通枪械通过引擎的 `BulletTrace` 扩展点选择正确的查询批次，保留原有弹药、霰弹和命中同步流程；受该接口限制，先按内容批次和普通对象选出最近命中，再额外执行一次选中的原生查询；尚未做实图性能验收。无命中时仍保留射线终点，避免开阔处的瞄准落点错误回到世界原点。雷电球遮挡查询忽略发射者自身；重力星先检查遮挡，再使用 `NpcSolid` 检查拉拽移动。

球形扫掠显式请求 `HitPosition`：飞行停在弹体中心，但爆炸、焦痕、火焰星和炸药包定位使用实际表面接触点，避免按扫掠半径悬空。炸药包附着物体旋转时，同时更新爆炸表面法线；火焰星继续随附着物体移动和旋转。

这些修复没有恢复全部原版机制：重力星仍采用部署后直接吸附约 2.9 秒的简化流程，没有触发等待和上浮阶段；原版全套充能／投掷蓄力、EMP 状态效果、折射和 Miles 分层混音仍未完整实现。专项运行检查覆盖 SMR 与六类投掷物的飞行、部署、起爆、附着移动和资源清理，不等于多人网络或逐帧视觉一致性验收。

## 距离衰减与攻击者伤害（2026-11-24）

挂载的多人 WeaponData 现在同时保留玩家／NPC 对普通目标／泰坦的四组直接命中伤害。近、远、极远距离之间采用两段线性插值，最后一段之外保持极远伤害；NPC 的距离字段可以独立覆盖。缺少 NPC 或护甲参数时继承普通曲线，显式的 `0` 仍为零。例如本机 R-201 多人脚本的玩家普通命中为 25 → 17 → 12，距离为 1500／2000／3500；NPC 普通命中为 10 → 8，对泰坦直接命中为 0，不再统一套用玩家伤害的 0.45 倍。手动创建且没有启用伤害配置的旧组件保留原有固定伤害行为。

玩家 hitscan、NPC 主武器和驾驶中的泰坦逐次选择相应曲线。霰弹只做一次原有弹丸数分摊；宿主修改基础伤害或核心倍率时按比例缩放。更换泰坦武装会同时更换曲线。飞行弹体在发射时保存配置、发射者类型与基础伤害，在直接命中位置计算距发射点的距离；切枪或修改武器不改变已经发出的弹体。爆炸、持续区域、近战和核心光束继续使用各自的伤害规则。

伤害衰减终点不再作为玩家 hitscan 射线的终点；普通子弹当前使用 16384 单位的引擎适配上限。NPC 的寻敌／交战范围和投射物寿命仍单独限制。这一上限和线性插值是本引擎实现，没有对零售原生判伤做逐帧一致性验收。护甲弱点要求、原版全部命中组倍率和减伤规则仍未完整恢复，不能把曲线数值相同视为完整伤害机制一致。

每颗 hitscan 弹丸仍通过引擎的命中申报接口到主机；因弹丸可命中不同距离和护甲，远程客户端现在逐颗申报，主机按自己的配置核对该颗伤害。开火表现仍按一次齐射同步，弹药按一次扣除。专项检查验证主机开火与申报校验方法，没有接受多客户端网络性能或反作弊验收。

## 第一人称外观和枪声

原版多人脚本的 `bodygroup*_name`／`bodygroup*_set` 应用于持枪模型，保留作者配置的机瞄等部件。第一人称枪口和抛壳随原版附件和动画事件触发，使用 Overlay 渲染层；NPC 使用世界枪口和世界层。

`WeaponAudio.cs` 独立处理枪声，不使用通用环境声音的模糊匹配。CAR 的原版脚本把弹壳落地事件放在 `fire_sound_1`，真正开火声来自首发／循环事件；现在按已核对的原版 Miles 样本族（CAR=`cbr101`、R-201=`r101`、SMR=`arl` 等）区分第一／第三人称、首发／循环／收尾和随机变体。连射保持一个循环，停止、换弹和收枪时结束；Hemlok 的三连发录音只启动一次。换弹声音要求武器和动作都匹配，避免把空仓换弹或拔弹匣声配给另一动作。

这些是原版音库录音，并未恢复 Miles 原生事件图、所有分层混音、环境 DSP、原版距离曲线或所有充能等级。部分武器只找到同武器的第三人称录音时使用该录音；无法确定的声音保持缺失，不串用其他武器。资源选择及解码检查也不等于与原版进行逐声试听验收。

## 当前简化与验收边界

这是基础技能与六种核心的本引擎适配。涡旋目前只格挡，不捕捉反射；强力护盾跟随机体且不替队友挡弹；北极星防御暂用电烟雾，尚无牵引陷阱或飞行核心。集束使用二十次独立局部爆炸，未生成原版随机子弹药实体。离子肩炮的完整蓄力、共享能量、相位、完整剑术／全部原版动画状态机仍未实现；激光核心自身已有蓄力与持续判伤。电弧波未施加原版减速。核心、登乘与HUD目前只接受本地玩家／监听主机驾驶，尚未扩展远程客户端驾驶。

图形原生检查使用实际零售挂载资源和生成后的官方组件包，但机体逻辑用例关闭了模型加载以隔离伤害与序列开销；这不等于八种泰坦的真人驾驶／外观验收或多客户端网络验收。工作区原有的未提交内容继续保留。
